# Tenrai Reference Web Wallet

A non-custodial wallet for Tenrai. The browser derives keys and signs transactions. The Node.js server relays chain requests and signed transactions through the Tenrai SDK.

## Run

Use Node.js 22.18 or later.

```sh
npm ci
npm run build
npm start
```

Open `http://127.0.0.1:28784`. Use `npm run dev` for local development with hot reload.

For production, serve the wallet over HTTPS through a reverse proxy on the same host. Keep the wallet bound to loopback and have the proxy set `X-Forwarded-For` from the client connection. Set deployment options in `.env` using `.env.example` as a reference. `TENRAI_NODE_URL` adds an operator-run node to the options in Settings.

## Wallet storage

The browser encrypts the recovery phrase and optional passphrase with AES-GCM and a password-derived key (PBKDF2-SHA256, 600,000 iterations). The network is bound to the encrypted record. Back up the phrase and passphrase before receiving funds.

The wallet commits signed payments and their input reservations to its sealed IndexedDB journal before submission. On reload it restores the signed transactions for retry and reconciliation. One browser lock coordinates public and private spending across tabs. When older records need manual recovery, unlock offers a download of the retained records.

## Checks

```sh
npm run check
npm test
```

Set `TENRAI_NATIVE_CAPTURE` to the absolute path of `synthetic-native-public-vectors.json`, generated by the Tenrai test runner with `browser-wallet/e2e-production.mjs --mode native --capture`. Set `TENRAI_REPO` to the node checkout to compare the pinned chain IDs with its genesis files.

The SDK is pinned in `vendor/tenrai-sdk`. When updating it, use the built npm package, remove its `prepare` hook and refresh the lockfile before running the checks.
